## 一、这个项目是什么

**WindowKeeper** —— Windows 桌面小工具，解决三个真实痛点：

1. 换环境（接投影、拔外接屏、笔记本拿回家）就要重新摆一遍窗口，纯重复劳动
2. Win+方向键只能贴边/最大化，不支持任意尺寸和比例
3. 多屏用户最容易踩的：还原后窗口跑到看不见的地方，而**窗口身份识别**才是整个程序最难的一环

一句话概括产品：**记录指定窗口的大小与位置 → 一键调整 → 可保存成预设 → 托盘常驻 + 全局热键触发。**

技术栈：Python 3.13 + PySide6(Qt) + Win32 API（ctypes / pywin32）。**仅支持 Windows。**

## 二、30 秒跑起来

```powershell
# 1. 装依赖（只有两个）
python -m pip install -r 01_WindowKeeper\requirements.txt

# 2. 跑回归（从任何目录都可以）
python 01_WindowKeeper\run_tests.py

# 3. 开发时直接跑源码
python 01_WindowKeeper\wk.py list          # 列出当前窗口
python 01_WindowKeeper\wk.py save 我的布局  # 存一个预设
python 01_WindowKeeper\wk.py apply 我的布局 # 还原
python 01_WindowKeeper\wk.py ui            # 开主界面
python 01_WindowKeeper\wk.py tray          # 托盘常驻

# 4. 打包成单个 exe
python 01_WindowKeeper\build.py
```

> **目录不对会报 `ModuleNotFoundError: No module named 'windowkeeper'`。**
> 本仓库所有测试与脚本都已改成用 `Path(__file__).resolve().parent.parent` 推导路径，
> 从任何目录运行都正常。如果你看到这个错，说明某个脚本又被写成了 `sys.path.insert(0, ".")` —— 修它。

## 五、红线（改代码前必须知道）

1. **`enable_per_monitor_v2()` 必须在任何窗口操作之前调用。**
   `wk_app.py` / `cli.py` 的 `main()` 第一件事就是它。不调用会拿到虚拟化的逻辑坐标——
   曾经因此让诊断报告把 2560x1600 的 150% 屏谎报成 1707x1067 @100%，而那份报告恰恰是用来排障的。

2. **还原跨屏窗口必须调两次 `SetWindowPos`，先位置后尺寸。**
   同一次调用里同时改显示器归属和尺寸，系统按旧屏 DPI 解释尺寸、落屏后按新屏重算，
   偏差 = 新DPI/旧DPI（实测 800x600 → 1200x900，正好 ×1.5）。这条已封装在 `apply_geometry()` 里，别绕过它。

3. **热键用 `RegisterHotKey`，不要换回 `keyboard` 库。**
   实测本机 keyboard 库「普通键 `a` 能收到、组合键回调 0 次」。用 `RegisterHotKey(None, id, ...)`
   把 WM_HOTKEY 投给调用线程的消息队列，而 `QApplication.exec()` 本来就在泵消息，**不需要任何后台线程**。

4. **`nativeEventFilter` 里不要直接动窗口。**
   用 `QTimer.singleShot(0, ...)` 推到下一轮事件循环，否则卡住消息循环。

5. **不要去掉 `tests\` 里的断言去「让测试通过」。**
   那些断言大多固化的是真踩过的坑（MSG 偏移 16、无修饰键必须拒绝、重复 setup 不能重复写日志）。

6. **日志不能成为崩溃源。**
   `log.py` 里每个 handler 创建都包在 try/except 里；`setup()` 幂等；`swallow()` 保持控制流不变只留痕迹。

## 七、给接手 AI 的三条忠告

1. **别信「看起来对」。** 本项目所有界面验证都走程序化断言（`tests\test_ui.py` 明确拒绝截图比对，
   因为截图证明不了数据对不对，换台机器换缩放率像素就全变）。请沿用这个做法。

2. **失败先看日志再猜。** 日志在 `%APPDATA%\WindowKeeper\logs\`，人类可读那份
   `windowkeeper.log` 记录了每个窗口的「期望坐标 vs 实际坐标 + 匹配分数 + 使用策略 + 是否跨屏」。
   界面上有「日志…」和「导出诊断包…」两个按钮，诊断包里含完整的显示器/DPI/预设摘要。

3. **改完必须跑 `run_tests.py`。** 它有 5 个默认套件（约 30 秒）+ 打包验收（`--all`）。
   涉及界面就顺手 `python 01_WindowKeeper\wk.py ui` 看一眼真窗口。
