# 01 · 项目说明

最后更新：2026-10-14 ｜ 版本：0.2.0

---

## 一、它解决什么问题

### 1. 换环境就要重摆窗口（最主要）

在公司接了外接屏、回家只剩笔记本、开会接投影——每次都要把 IDE、浏览器、终端、
聊天工具一个个拖到原来的位置和大小。**这是纯重复劳动，而且每次都要重来。**

### 2. Win+方向键不够用

Windows 自带的贴边/最大化只能给固定的几种尺寸，不支持「我要左边 60% 宽度但满高」这类自定义比例。

### 3. 多屏用户最怕的：还原后窗口跑到看不见的地方

外接屏拔掉后，原本在负坐标屏上的窗口还原到了不存在的区域。程序必须能识别
「显示器配置变了」并做合理降级。

### ★ 隐藏的难点：窗口身份识别

**这才是整个程序最难的一环，也是最容易被低估的。** 客观现实（本机实测）：

- `explorer.exe` 有 4 个窗口，**类名完全相同**
- `msedge.exe` 有 4 个窗口，**类名完全相同**
- `video-player.exe` 有 2 个窗口，**进程名 + 类名 + 标题全部相同** → 指纹根本无法区分

所以「这个窗口是不是我上次记的那个」无法用单一字段判断，只能加权评分。
本项目用 `matcher.py` 的四维加权（进程名 45 / 类名 20 / 标题精确 30 / 标题模糊 18 / 几何相近 12），
阈值 55 分算匹配、85 分算强匹配，**孪生窗口需要用户在界面上手动指定**。

## 二、给谁用

| 用户 | 典型场景 |
|---|---|
| 多屏办公 | 公司双屏 ↔ 家里单屏，一键切换布局 |
| 投屏/会议 | 接投影前把资料窗口摆好，散会后一键还原 |
| 固定工作流 | 「写代码」「做设计」「看视频」三套布局一键切换 |
| 笔电用户 | 插拔外接屏不用重新摆 |

**不适合**：需要管非 Windows 平台、需要管管理员权限程序、需要管全屏独占游戏。

## 三、功能清单

### 已完成 ✅

| 功能 | 说明 | 对应模块 |
|---|---|---|
| 捕获当前布局 | 枚举所有可见窗口，记录位置/尺寸/显示器/指纹 | `matcher.py` `engine.py` |
| 保存为预设 | 存成命名预设，可绑全局热键 | `store.py` |
| 一键还原 | 精确回位，含跨屏两步协议、最小化/最大化预处理 | `engine.py` |
| 预演（dry-run） | 只算不动，先看结果再决定 | `engine.py` `cli.py -n` |
| 全局热键 | Win32 RegisterHotKey，无需后台线程 | `tray.py` |
| 托盘常驻 | 菜单一键还原、捕获、开主界面 | `tray.py` |
| 图形界面 | 深色主题，预设列表 + 布局缩略图 + 窗口明细 + 显示器页 | `ui.py` `monitor_map.py` |
| 显示器缩略图 | 按真实相对位置绘制，支持负坐标屏 | `monitor_map.py` |
| 显示器变化自适应 | 四级几何回退策略，拔屏后按比例降级 | `store.py` `resolve_geometry()` |
| 导入导出 | 预设可导出成文件分享/备份 | `store.py` `cli.py` |
| 命令行 | 13 个子命令，可脚本化 | `cli.py` |
| 日志 | 双格式（人读 + 机器读）、自动轮转、崩溃钩子 | `log.py` |
| 诊断包导出 | 一键打包环境报告 + 全部日志 | `log.py` |
| 单文件打包 | 26.2MB 单 exe，无需装 Python | `build.py` `wk.spec` |

### 未做 / 受限制 ⚠️

| 项 | 状态 | 原因 |
|---|---|---|
| 管理员权限的窗口 | ❌ 管不了 | UIPI 限制，普通权限进程无法操作高完整性进程的窗口 |
| 全屏独占程序 | ❌ 管不了 | DirectX 独占全屏不在窗口管理器控制下 |
| UWP 应用 | ⚠️ 部分受限 | `ApplicationFrameWindow` 类需要特殊处理，已列入不可控名单 |
| 孪生窗口自动区分 | ⚠️ 需人工 | 指纹完全相同时无法自动判断，界面提供手动指定 |
| 自动开机启动 | ❌ 未内置 | 手动把快捷方式丢进 `shell:startup` 即可（README 有说明） |
| 布局随显示器插拔自动切换 | ❌ 未做 | 值得做，见后续计划 |
| 窗口内部分栏记忆 | ❌ 未做 | 只能记忆整个窗口，不能记忆 IDE 内部面板布局 |

## 四、产品设计取舍（为什么是这样）

| 决策 | 理由 |
|---|---|
| **单个 exe 三合一**（无参数=托盘，带子命令=CLI） | 打两个 exe 要各拖一份 PySide6，多 100MB+；用户也不用记「哪个是哪个」 |
| **界面刻意不做截图比对测试** | 截图只能证明「看起来对」，证明不了数据对；换机器换缩放率像素全变 |
| **日志同时写两份格式** | 用户用记事本打开要看人类可读的；出问题需要机器可读字段做分析 |
| **「清空日志」按钮** | 用户排查完想清干净；但不能因此让日志系统卡死（已修过这个 bug） |
| **热键设置对话框让用户按键而不是填字符串** | 手打「ctrl+alt+1」太容易写错，且容易漏掉「必须有修饰键」这个危险点 |
| **不用 keyboard 库** | 实测组合键收不到，且它需要在持续泵消息的线程上，与 Qt 主循环竞争 |
| **不引入任何第三方 UI 框架/图标资源** | 图标用 QPainter 画，打包单文件时不用带资源，也不再增加依赖 |
