## 四、下一步优先级

按「影响大 × 费力小」排序。**前两项是真正值得做的。**

### P1 · 布局随显示器插拔自动切换（推荐先做）

**为什么**：这是多屏用户的**最高频痛点**。现在接到投影/拔掉外接屏后，用户得手动点一次预设。
自动切换能让程序从「偶尔用的工具」变成「感觉不到但一直在起作用」的基础设施。

**怎么做**：
- `ui.py` 已有 `_check_monitors()` 每 2.5 秒比对 `_monitor_signature()`（因为显示器热插拔
  不会发通知给普通窗口，只能定时比对）——**这套机制已经在了，只需接上动作**
- 给 `Preset` 增加可选字段 `auto_for_monitors`（保存时的显示器签名）
- 检测到签名变化时，找出签名匹配的预设自动应用
- 必须给「开关」和「延迟」，且默认关闭——自动移动窗口是侵入性行为，不能在用户没预期时发生

**风险**：误触发会打扰用户。建议首次启用时用气泡通知告知「已自动切换到 XX 布局」。

### P2 · 预设分组/标签

**为什么**：预设一多（10 个以上）列表就难找。「工作/娱乐/演示」分组几乎零成本。

**怎么做**：`Preset` 加 `group: str = ""` 字段，`ui.py` 的 `QListWidget` 换成 `QTreeWidget`
或加分组筛选下拉框。**`SCHEMA_VERSION` 要升到 2**，并写迁移逻辑（旧预设 group 默认空串）。

### P3 · 窗口内的相对位置记忆（费力大）

**为什么**：「左边 60% 宽度满高」这类比例现在只能记绝对像素，换屏后靠比例回退近似还原。

**怎么做**：`store.WindowRef` 已有 `rel_in_work` / `rel_size`，**数据模型已经支持**，
只差在 UI 上让用户选择「按像素记」还是「按比例记」。

### P4 · 开机自启开关（费力小）

现在只能手动把快捷方式丢进 `shell:startup`（README 有说明）。
在界面上加个复选框写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 即可。

### P5 · 多显示器 DPI 变化的实时响应

现在预设存的是物理像素；如果用户改了缩放率（不换屏），还原位置会偏。
可在 `Preset` 里存保存时的 DPI，变化时提示。

### 明确不建议做的

| 想法 | 为什么不做 |
|---|---|
| 跨平台（macOS/Linux） | 整个架构建立在 Win32 上，等于重写；且用户群是 Windows 多屏办公 |
| 云同步预设 | 预设是本地显示器配置相关的，换机器就失效；导出/导入文件已够用 |
| 窗口内部分栏记忆（IDE 面板） | 需要注入目标进程或读它私有配置，极其脆弱且侵入性强 |
| 自动识别「该用哪个预设」 | 猜错的代价（窗口乱跳）远大于收益；手动 + 热键已经很高效 |
| 重构成插件架构 | 当前 9 个模块职责清晰、无循环依赖，重构收益为零而风险不小 |
