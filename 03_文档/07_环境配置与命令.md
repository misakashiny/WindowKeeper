## 一、环境

### 本机验证过的环境

| 项 | 版本 |
|---|---|
| 操作系统 | Windows 11（仅支持 Windows） |
| Python | 3.13.2 |
| PySide6 | 6.12.0 |
| pywin32 | 312 |
| PyInstaller | 6.12.0（仅打包需要） |

### 安装

```powershell
python -m pip install -r 01_WindowKeeper\requirements.txt

# 打包还需要 PyInstaller（requirements.txt 里注释掉了）
python -m pip install pyinstaller
```

**只有两个运行时依赖**：PySide6 与 pywin32。
`keyboard` 库已弃用（原因见 [02_架构与模块.md](02_架构与模块.md) 的「热键」一节），**不要装**。

### 数据与日志位置

| 内容 | 路径 |
|---|---|
| 预设 | `%APPDATA%\WindowKeeper\presets.json` |
| 日志（人读） | `%APPDATA%\WindowKeeper\logs\windowkeeper.log` |
| 日志（机器读） | `%APPDATA%\WindowKeeper\logs\windowkeeper.jsonl` |
| 诊断包 | 桌面 `WindowKeeper诊断_YYYYmmdd_HHMMSS.zip` |

即 `C:\Users\<你>\AppData\Roaming\WindowKeeper\`。
界面上点「数据文件夹」按钮可直接打开。

**删除即卸载**：删掉 exe 和上面这个数据目录，系统里不留任何东西。

## 二、日常命令

### 跑测试

```powershell
python 01_WindowKeeper\run_tests.py            # 默认 5 套件（约 30 秒）
python 01_WindowKeeper\run_tests.py --all      # 加打包验收（需先 build）
python 01_WindowKeeper\run_tests.py -k log     # 只跑日志套件
python 01_WindowKeeper\run_tests.py --list     # 列出套件
```

> `run_tests.py` 内部固定 `cwd=ROOT`，**从任何目录运行都可以**；
> 并且对测试输出的编码做了自适应（utf-8 / gbk / cp936），不要求各脚本自律。

### 跑源码

```powershell
python 01_WindowKeeper\wk.py ui            # 开主界面（不带托盘）
python 01_WindowKeeper\wk.py tray          # 托盘常驻
python 01_WindowKeeper\wk.py list          # 列出当前可用窗口
python 01_WindowKeeper\wk.py monitors      # 列出显示器
python 01_WindowKeeper\wk.py --help        # 全部子命令
```

### 打包

```powershell
python 01_WindowKeeper\build.py
# → 01_WindowKeeper\dist\WindowKeeper.exe（约 26.2MB）
```

`build.py` 会自动 `taskkill` 掉正在运行的 `WindowKeeper.exe`，
否则构建的**最后一步**会报 `PermissionError [WinError 5]`（误导性极强）。

## 三、CLI 子命令

| 子命令 | 别名 | 说明 |
|---|---|---|
| `list` | `ls` | 列出当前可用窗口 |
| `windows` | `win` | 同 list |
| `monitors` | `mon` | 列出显示器（名称/分辨率/缩放/主屏） |
| `save <名>` | | 捕获当前布局存为预设。`-a/--all` 含最小化、`-f/--force` 覆盖、`--only <进程名…>` 只存指定程序 |
| `apply <名\|序号>` | | 还原预设。`-n/--dry-run` 预演、`--no-activate` 不激活窗口。**支持前缀包含匹配**（唯一命中才用） |
| `show <名>` | | 查看预设内容 |
| `delete <名>` | `rm` | 删除预设 |
| `rename <旧> <新>` | `mv` | 重命名 |
| `hotkey <名> <键>` | | 设置全局热键，如 `ctrl+alt+1` |
| `export [文件]` | | 导出全部预设 |
| `import <文件>` | | 导入预设（同名自动改名） |
| `tray` | | 启动托盘常驻 |
| `ui` | `gui` | 打开主界面 |

**全局参数**：`-v/--verbose` 把日志实时打到控制台。

输出状态前缀含义：

| 前缀 | 含义 |
|---|---|
| `[OK]` | 精确还原 |
| `[WARN]` | 有偏差但在容忍范围 |
| `[LIMIT]` | 受窗口自身约束（如最小尺寸）而受限 |
| `[MISS]` | 未找到匹配窗口 |
| `[DENY]` | 被拒绝（如管理员权限程序） |
| `[FAIL]` | 其他错误 |

## 四、常用操作片段

### 保存当前布局并绑热键

```powershell
python 01_WindowKeeper\wk.py save 工作布局
python 01_WindowKeeper\wk.py hotkey 工作布局 ctrl+alt+1
python 01_WindowKeeper\wk.py apply 工作布局 -n      # 先预演看结果
```

### 只保存几个程序

```powershell
python 01_WindowKeeper\wk.py save 编程 --only Code.exe WindowsTerminal.exe chrome.exe
```

### 备份/迁移预设

```powershell
python 01_WindowKeeper\wk.py export 我的布局.json
python 01_WindowKeeper\wk.py import 我的布局.json
```

### 开机自启

把 `WindowKeeper.exe` 的快捷方式丢进 `shell:startup`（运行框输入 `shell:startup` 回车）。

### 完全备份整个项目

```powershell
robocopy "D:\AI Dsh\软件制作" "D:\AI Dsh\软件制作\_backup_$(Get-Date -Format yyyyMMdd)" /E
```

> **本项目不是 git 仓库**，备份是唯一的回退途径。

## 五、排障手册

### 第一步：永远先看日志

```
%APPDATA%\WindowKeeper\logs\windowkeeper.log
```
或界面上的「日志…」按钮，或「导出诊断包…」把环境报告 + 全部日志打包。

日志里每个窗口都有一条「决定」级别的记录，含**全部证据**：

```
13:08:54.262  决定  已还原：msedge.exe  [kind=ok  requested=874,155 1132x1121
              actual=874,155 1132x1121  min_track=591x140  score=65
              ambiguous=True  strategy=显示器未变，绝对坐标  cross_monitor=False]
```

字段含义：

| 字段 | 含义 |
|---|---|
| `requested` / `actual` | 期望坐标 vs 实际坐标 —— 一眼看出差在哪 |
| `score` | 匹配分数（≥55 算匹配，≥85 强匹配） |
| `ambiguous` | 是否存在同分孪生候选（需人工指定） |
| `strategy` | 用了四级回退里的哪一级 |
| `cross_monitor` | 是否跨显示器（跨屏会走两步协议） |
| `min_track` | 窗口自身的最小尺寸约束 —— **偏差来自这里就不是 bug** |

### 常见问题对照

| 症状 | 先查什么 |
|---|---|
| 窗口没回到原位 | 日志里那条记录的 `requested` vs `actual`；再看 `score` 是否为 0（没匹配上） |
| 报 `[MISS]` 未找到 | 目标程序可能已退出；或标题/进程名变了（看 `reasons` 字段） |
| 报 `[DENY]` | 目标是管理员权限程序，受 UIPI 限制，无法操作 |
| 尺寸差几像素 | 看 `min_track` —— 窗口自己声明的最小尺寸约束，不是程序算错 |
| 显示器信息不对 | 检查是否调用了 `enable_per_monitor_v2()`（诊断报告里有这项） |
| 热键没反应 | 日志里看「热键注册完成」的 `registered` 数；为 0 说明注册失败（可能 1409 被占用） |
| 托盘图标不见了 | Win11 默认隐藏不常用图标，需在通知区域设置里手动拖出 |
| 主界面打不开 | 若已有托盘在跑，双击托盘图标即可（不会开第二个实例） |
| 打包报 `WinError 5` | 有 `WindowKeeper.exe` 在运行，先关掉 |
| 测试报 `ModuleNotFoundError` | 某个脚本被写成了 `sys.path.insert(0, ".")`，改成 `Path(__file__).resolve().parent.parent` |

## 六、环境陷阱清单（踩过的）

| 陷阱 | 真相 |
|---|---|
| PowerShell 不支持 bash heredoc（`<<'PY'`） | 多行 Python 要写成脚本文件 |
| PowerShell 把正则里的 `?` 当命令解析 | 含正则的 `python -c` 要写成脚本文件 |
| 控制台是 GBK，stderr 显示乱码 | **文件是正确的 UTF-8**；用 read/编辑器看正常 |
| `python xx.py 2>&1` 报 `exit code 1` | PowerShell 把 stderr 当错误；只要 stdout 显示通过就是成功 |
| 单文件 exe 看起来没启动 | 它是**两个进程**，取 tasklist 第一行拿到的是引导进程 |
| `console=False` 的 exe 用 `Popen(pipe)` 抓不到输出 | 它会阻塞在 Qt 事件循环；改用 shell 文件重定向 |
| `user32.GetProcessDpiAwarenessContext` 抛 `AttributeError` | 老系统不导出该函数，必须 `getattr(..., None)` 兜底 |
| 诊断报告里用 `⚠` 字符导致 `UnicodeEncodeError: 'gbk' codec` | GBK 环境打开会打断整条生成链路，用 ASCII 替代 |
| Win11 记事本默认最大化打开 | `IsZoomed` 可能漏检无边框最大化；测试要先 `unmaximize()` |
| `save` 遇同名要求 `--force` | **这是正确行为**，防止误覆盖 |
