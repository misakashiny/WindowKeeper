## 二、审计发现的问题（按严重度）

### P0 —— 阻断 AI 接手

**① 核验知识全部埋在代码里，没有可读文档**
- `probe\CONCLUSIONS.py`（8.5 KB / 158 行）**是伪装成 .py 的结论文档**：内容是一个 `CONCLUSIONS = r"""..."""` 字符串，`main()` 只负责打印。这正是「最精华的实测结论」，却以源码形式存在，新 AI 极难发现。
- 结论 4（跨屏必须两步 SetWindowPos）、结论 2（孪生窗口现实）、最小化哨兵值 `(-32000,-32000) 160x28` 等关键事实，目前只散落在各模块 docstring 里。
- **没有任何架构文档、进度文档、BUG 清单、迭代日志。**

**② 根目录无编号、无中文命名，且被无关项目污染**
- 新 AI 打开根目录，第一眼看到 `SWExportSTL\`（含 2.7 MB SolidWorks DLL），无法判断哪个才是本次任务的项目。

**③ 没有统一的测试入口**
- 新 AI 想验证「功能是否完好」，必须自己读 6 个文件头才能拼出运行命令。

### P1 —— 影响可维护性

**④ README 混装了两类读者**
300 行里同时写给「只想双击 exe 的用户」和「要改代码的开发者」，还包含 6 条开发期的踩坑长文。两类读者都要读完整篇才能找到自己要的。

**⑤ README 缺日志章节（功能已实现但文档未记）**
日志功能（T13、52 项测试、exe 实测落盘）已完整实现，但 README 全文只有 1 处提到 `probe\`，**完全没有日志章节**——用户根本不知道日志在哪、怎么导出诊断包。

**⑥ probe 目录混入 11 个 0 字节调试残留**
```
_diag_ui_err.txt / _diag_ui_out.txt / _e2e_err.txt / _e2e_out.txt
_pkg_tray_err.txt / _pkg_tray_out.txt / _pkg_ui_err.txt / _pkg_ui_out.txt
srcui_err.txt / ui_err.txt
```
另 `ui_out.txt`(157 B)、`monitor_map_preview.png`、`tray_shot.png`、`ui_shot_1.png` 是临时产物。
`probe\CONCLUSIONS.py` 是文档误放（见 ①）。`probe\_audit_read.py` 是本次审计的临时脚本。

**⑦ 存在 `windowkeeper\__pycache__\`（约 276 KB 的 .pyc）**
打包/运行残留。`build\` 中间目录已被 build.py 自动清理（现状不存在，符合预期）。

### P2 —— 建议改进

**⑧ 缺少依赖清单与一键测试脚本**
无 `requirements.txt`（依赖仅 3 个：PySide6 / pywin32，且代码里 `keyboard` 已弃用不装）。无 `run_tests.py`。

**⑨ `wk.py` 与 `wk_app.py` 同名族易混淆**
`wk.py` 是源码 CLI 入口（4 行）；`wk_app.py` 是打包入口（含 DPI 声明与三合一分发逻辑）。两者功能不重复（`wk_app.py` 的 docstring 已解释），但文件名过于接近，建议在文档里明确区分。

## 四、需要确认的风险点

**SWExportSTL 的注册状态（已核实）**

审计时检查了四个注册表位置与桌面快捷方式，结论是**它当前未注册到系统**：

| 检查项 | 结果 |
|---|---|
| `HKLM\SOFTWARE\Classes\CLSID\{7C4A9E21-...}\InprocServer32` | 未注册 |
| `HKCU\Software\Classes\CLSID\{...}\InprocServer32` | 未注册 |
| `HKLM\SOFTWARE\SolidWorks\AddIns\{...}` | 未注册 |
| `HKLM\SOFTWARE\SolidWorks\SOLIDWORKS 2024\Addins\{...}` | 未注册 |
| 桌面四个快捷方式（STL悬浮窗 等） | 均不存在 |

（真实 CLSID 从 `SWExportSTL\build\regtest\out.reg` 取得：`{7C4A9E21-3F8B-4D62-A1C5-9E4B7F0D2A38}`）

**推论**：SWExportSTL 的 README 声称「安装后桌面有四个快捷方式」，但实际一个都没有，注册表也全空 —— 它**可能从未安装成功，或装过又被卸载**。因此整体移动它不会破坏任何正在运行的组件。

**但仍有不确定性**：用户是否手动在 SolidWorks 里启用过它、是否有别的机器依赖它。
