## 四、整理过程中发现并修复的 BUG

### B20 · 统一入口误判测试失败

跑 `run_tests.py` 时 `test_log.py` 显示 52/52 通过，入口却报失败。

**根因两条**：
1. `test_log.py` 没有重配 stdout 编码，在 GBK 控制台输出 GBK 字节，入口用 utf-8 读成乱码，正则抓不到「通过 N / 共 M」
2. 该脚本有一条测试**故意**测「无占位符时传位置参数」，logging 会把诊断写到 stderr

**修复**：入口层做编码自适应（依次试 utf-8 / gbk / cp936），并规定「计数说通过但退出码非 0」时以计数为准。
**教训**：不要要求每个测试脚本自律地处理编码，入口层兼容更可靠。

### B21 · 零尺寸窗口被枚举进预设

`test_engine.py` 从 51/51 掉到 49/51：
```
❌ 所有窗口都有几何
❌ 指纹几何完整  —  无效: ['setup.exe']
```

**根因**：系统上有个 InstallShield 安装程序（`setup.exe`，类 `InstallShield_Win`），
它弹出瞬间 `IsWindowVisible=True`、`IsIconic=False`，但 `GetWindowRect` 返回
`(1280, 720, 1280, 720)`——**宽高都是 0**。现有的四条过滤规则全都不覆盖这种情况。

**修复**（`matcher.py`，在最小化判断之后）：
```python
if rect[2] - rect[0] <= 0 or rect[3] - rect[1] <= 0:
    return True
```

**教训**：窗口过滤规则要覆盖「几何无效」这一整类，而不是逐个列举已知的无效类型。

### B22 · 端到端验收用记事本导致偶发失败（最有价值的一条）

`test_e2e_user.py` 的最终断言偶发失败，**每次报的实际值都不一样**：
```
实际 (0, 0, 0, 0)
实际 (-32000, -32000, 160, 28)
```

这两个值极具误导性：`(-32000,-32000) 160x28` 是最小化哨兵值，看起来像「还原把窗口最小化了」；
`(0,0,0,0)` 看起来像「窗口被销毁了」。

**但引擎日志是清白的**：
```
15:49:06.405  决定  已还原：Notepad.exe  [hwnd=26677034  requested=320,260 760x520  actual=320,260 760x520]
15:49:06.406  决定  已还原：Notepad.exe  [hwnd=10556154  ...]
15:49:06.453  INFO  还原「__验收临时__」结束：3/3 精确，0 受限，0 有偏差，0 失败
```

**根因**：测试用 `--only Notepad.exe` 存预设，但 `--only` **只能按进程名过滤，无法按 hwnd 精确指定**。
开发机上几乎总是开着别的记事本（那一轮正好开着用户的「项目交接文案.txt」），
于是预设里有 3 个 Notepad 窗口，还原时被一并操作，测试监视的窗口被外部因素带偏。
**这是测试隔离缺陷，不是引擎 bug。**

**修复**（三处）：
1. 实验对象从 `notepad.exe` 换成 **`charmap.exe`（字符映射表）**——进程名测试独占，
   普通用户不会开着它；同样是传统 Win32 程序，响应 `SetWindowPos`
2. 新增守卫「目标程序是测试独占的（无同名干扰窗口）」
3. 新增守卫「预设里只有本测试的那一个窗口」

**回归**：连跑三遍全部 13/13，偶发完全消失。

**教训**：验收测试的实验对象必须是**测试独占**的资源。只要可能与「同类的其他实例」
冲突，就一定会偶发失败，而且报出来的几何值会把人引向完全错误的方向——
这次差点去查引擎的最小化处理逻辑。

## 八、给用户的功能建议（此前一直未交付的第 ① 条）

原本的 m00663 提问「有什么功能上的建议吗」，一直没正式答复。整理期间观察下来，
按「影响大 × 费力小」排序：

### 高价值 / 低投入（建议优先做）

1. **布局随显示器插拔自动切换** —— 最痛的真实场景：笔记本接上/拔掉外接屏，
   所有窗口要重摆。引擎已经能检测显示器变化（`monitors_changed()`），
   UI 也已有 2.5 秒轮询机制，**只差把动作接上**。可以让每个预设可选绑定
   「显示器配置指纹」，配置一变就自动套用对应预设。

2. **预设分组/标签** —— 预设一多，列表就变成一长串。「工作」「游戏」「演示」
   分组能显著改善查找，且纯 UI 层改动，不动引擎。

3. **还原前自动快照** —— 万一还原结果不理想，用户想退回原状。还原前把当前
   布局悄悄存成一个「_自动快照_」预设即可，成本极低但能救命。

### 中等价值

4. **窗口匹配失败时的手动指定入口** —— 现在孪生窗口（`ambiguous=True`）只在
   报告里说明，用户无法补救。若在预览界面列出候选窗口让用户点选一次并记住，
   这个限制就基本消失了。

5. **相对位置记忆模式** —— 按显示器工作区的百分比存，而不是绝对像素。
   好处是分辨率变化后布局仍合理。

6. **热键触发时的画面提示** —— 现在按了热键只弹托盘通知，容易错过。
   可以做一个短暂的半透明浮层，显示正在还原哪个预设。

### 低优先级 / 可选

7. **开机自启开关** —— 现在要手动丢快捷方式进 `shell:startup`，做成界面开关更友好。
8. **预设导入导出支持拖拽** —— 现在是文件对话框。
9. **命令行补全 / 交互模式** —— 对重度 CLI 用户有用。

### 明确不建议做

- **不做窗口内容截图预览** —— 成本高、隐私敏感、对「还原布局」这个核心目标没有帮助
- **不做跨平台** —— 整个实现建立在 Win32 上，跨平台等于重写
- **不做云同步** —— 预设是本地几十 KB 的 JSON，导入导出已够用
